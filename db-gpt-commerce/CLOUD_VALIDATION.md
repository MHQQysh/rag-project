## 运行资源与修复

最初的启动预热模式曾触及内存限制并造成响应卡顿，随后发生一次 DB-GPT 服务的 OOM 终止。此过程未作为部署成功记录。

定位到官方 `CodeServer` 在启动期预热 Lyric 代码执行进程；观察到两个 Python worker 各占约 250 MiB。新增 `COMMERCE_LAZY_CODE_SERVER=1`，只跳过预热，保留首次实际代码调用的初始化流程。新的生命周期测试覆盖首次调用、重复调用和关闭，不代表在这台机器上完成了通用代码任务压力测试。

最终配置保留 700 MiB 硬上限，不设置 MemoryHigh 软限制；调试期间临时调整过 swappiness，完成按需启动适配后已恢复服务器原值 **0**。最终进程内存峰值 **592,838,656 bytes，约 565.4 MiB**，该服务自身 swap 为 0；系统仍可能保留调试期间其他进程已换出的页面。

## 验证边界

- 没有配置 embedding 模型，知识库向量检索和数据库向量摘要尚不可用；专用电商分析不依赖它们。
- 仅验证了顺序演示任务，没有验证双平台同时运行重型沙箱任务或高并发。首次调用通用代码工具仍会加载额外进程，小内存服务器可能再次达到上限。
- 没有新建 DB-GPT 公网入口。另一个 DeerFlow 会话已记录该域名的云服务商备案拦截；服务器内可用不能等同于公众可访问。
- 数据均为模拟数据；只验证了限定地区和月份的收入分析，不代表任意真实企业 SQL 都正确。
- 证据包不包含完整数据库备份，复算需要保存相同的数据快照。
- GitHub 仓库仅包含代码、部署说明和公开模拟验收结果；模型密钥、SSH 私钥、会话数据库和服务器环境文件不在提交范围内。
