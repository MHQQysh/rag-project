# 原版 DeerFlow 云端部署

## 现在怎样打开

当前部署的域名入口是 https://deerflow.shihongyuan.cn 。注意：2026-10-06 后续外网检查出现阿里云备案拦截与部分 HTTPS 连接重置，公网可用性仍待确认。服务器内部验证不能替代外部访客验收。

部署时也使用过本机 2028 端口的 SSH 通道进行验收；它需要个人电脑另行配置，不是仓库自带的公共访问服务。服务器服务已设为开机启动。

本机通道地址只适用于建立通道的电脑。GitHub Pages 上的 `/rag-project/deerflow-web/` 是之前的轻量版入口，与此次原版部署不同。

## 使用方式

2026-10-06 验收：原版网页登录、DeepSeek 调用、Python 工具执行、输出文件生成及下载已跑通。测试会话要求实际执行 `17*19`，生成 `result.txt`；服务器与本机下载的文件内容均核对为 `323`。小机器冷启动与执行明显偏慢，成功的一轮约 3 分钟；不是大模型本地推理导致。DNS 与 HTTPS 配置已完成；在服务器内通过域名请求登录页返回 200，后端就绪检查通过。后续公网拦截状态见上文。

- “新对话”：创建独立会话；左侧“对话”查看历史。
- “新建项目”：组织相关对话。
- 输入框旁的模型菜单：选择 DeepSeek Flash 或 Pro。
- 模式菜单：按原版界面选择任务模式；多 Agent 会增加 API 消耗和运行时间。
- 附件按钮：上传资料；生成的文件会在回答中出现下载入口。
- “能力中心”：查看和配置技能及工具。需要额外第三方密钥的能力须另行配置。

## 部署结构

浏览器 → HTTPS 域名 → ECS Nginx（443）→ Next.js 网页（3000）及 Python Gateway（8001）→ DeepSeek API / AIO Docker 沙箱。

采用本地已有 DeerFlow 2.1.0 源码快照，提交 `a58ab484a641fd5928ae512ad21c5c7fd7a18c18`。初次部署没有为缩小功能重写业务代码；后续新增了演示登录，见本目录 README。初次部署在云端 `backend/packages/harness/deerflow/community/aio_sandbox/backend.py` 将沙箱启动等待常量从 60 秒改为 180 秒，原文件保存在同目录 `.py.before-ecs-timeout` 备份中。前端在本机 WSL 构建为生产包，上传云端运行；后端按锁定版本安装依赖。下载加速采用清华 PyPI 镜像，依赖版本与导出的锁文件保持一致。

服务器主要目录：

| 路径 | 用途 |
| --- | --- |
| `/opt/deerflow` | 原版源码与配置 |
| `/opt/deerflow/frontend-runtime` | 前端生产运行包及 Node |
| `/opt/deerflow/backend/.venv` | Python 运行环境 |
| `/opt/deerflow/config.yaml` | 模型、工具、资源与并发设置 |
| `/etc/deerflow/model.env` | 模型密钥，勿提交到 GitHub |
| `/etc/deerflow/runtime.env` | 运行环境与认证密钥，勿公开 |
| `/var/lib/deerflow` | SQLite、对话状态、用户文件及运行数据 |

## 小内存服务器的设置

服务器实际物理内存约 1.6 GiB，已有 2 GiB swap。模型推理走 API，无需 GPU。

- Gateway 单进程，子 Agent 同时运行上限 1，其余排队。
- LLM 并发设置为 2。
- 每个沙箱内存限制 768 MiB、CPU 限制 1.5 核，闲置回收 180 秒。额外的 code-server 和 JupyterLab 网页服务关闭，保留沙箱 API、Python 命令执行和浏览器组件。
- 定时任务执行暂未启用；开放注册关闭，管理员已通过网页初始化。
- 可保存多个对话；建议一次运行一个复杂任务。多个会话同时执行、浏览器自动化或大文件处理仍可能超出这台机器资源。

## 运维

在服务器执行：

```bash
systemctl status deerflow-gateway deerflow-frontend nginx redis-server --no-pager
curl http://127.0.0.1:8001/health/ready
journalctl -u deerflow-gateway -n 80 --no-pager
docker ps
free -h
df -h /
```

修改配置后重启 Gateway；修改前端运行环境后重启前端：

```bash
systemctl restart deerflow-gateway
systemctl restart deerflow-frontend
```

备份需包含 `/var/lib/deerflow`、模型配置及受保护的环境文件。正在写入的 SQLite 不宜只复制单个数据库文件；维护窗口停止服务后整体备份，或使用 SQLite 备份接口。

公网入口：https://deerflow.shihongyuan.cn。已配置 HTTPS、可信来源、HTTP 自动跳转及证书自动续期后的 Nginx 重载。后端和沙箱端口仅在服务器内部监听。原站 https://shihongyuan.cn 验证返回 200，仍由 GitHub Pages 提供服务。
